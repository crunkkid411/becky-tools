Same binary, four pipelines

Every variant shares intake, transcript, the becky-cut silence map, whole-stream analysis, cut points, breath check, VEGAS build, edit check, markers and report. Only step S5 swaps engines — that is the worktree.

What each branch costs

D-QWEN runs free on this PC; D-STACK spends a few cents on System One; D-S1 spends a few cents across all three voters. All decisions are cached per model+guidance; --fresh re-decides.

Where your hunch was right

System One IS underused: today it only answers two multiple-choice questions per sentence to decorate the transcript for Qwen/Gemma (stack), or votes as one of three (together). It never touches cut points, breaths, censor, assets, or QA. See BUILD-PROMPTS.md #12.

Comparison · does --model qwen differ from --video?

Yes — meaningfully, but NOT by reinventing the wheel

Verified against the source (becky-go/cmd/livestream): the spine functions (transcribe call, edges.go, breath.go, vegas.go, verify.go) are literally the SAME code paths in both workflows. What differs is step S5 (the decision engine) and everything after S9 (the finishing half).

S5engine

Decision philosophy flipped

--model qwen: Qwen3.5-4B labels EVERY sentence keep/cut, Gemma-E4B reviews only the risky targets, conclude() merges. --video: rewritten 2026-10-13 "the openshorts way" after your verdict that voting every sentence was worse than simply removing silences — Gemma-4 12B reads parts and names ONLY exceptions (not-for-viewers + retakes), code confirms every retake against the actual words, the hesitation filter is pure code, on-camera instructions are parsed, and the viewer-read may only restore.

Meaning
Claude replaced the decision layer wholesale (your sign-off is recorded in coarse.go's header comment) — it did NOT fork or rewrite the spine. No hidden second implementation exists.
4bmodule

Visual moments run ONLY on the livestream branches

The gesture/put-back machinery (moments.go) plus face zooms: active for qwen/stack/systemone, explicitly disabled for --video ("random movements", 2026-10-13). Live-chat detection (Q3) likewise only makes sense for footage that started life as a stream.

So
"same steps minus chat removal" is close but incomplete: --video ALSO adds thinking-islands, second listen, tighten, grade, censor, looks/motion, show-intent assets and upload copy — none of which the qwen branch runs.
ENDendpoint

Both branches still stop at the timeline

Neither renders, neither levels audio, neither does SFX/music/QA-converge. The qwen branch additionally has no grade and no censor — its output is rougher than --video's, deliberately: livestream repurpose edits were meant for human hands from the start.
