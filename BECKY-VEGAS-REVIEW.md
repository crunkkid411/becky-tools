## Command Reference: What Worked and What Didn't

This section documents every `becky-vegas` command attempted during this review, its invocation, whether it succeeded, and notes for future agents.

### How the client is invoked

- **Binary:** `X:\AI-2\becky-tools\becky-go\bin\becky-vegas.exe`
- **Syntax:** `becky-vegas <command> [key=value ...]`
- **Exit codes:** 0 = success, 1 = VEGAS refused/failed (reason in JSON), 2 = no VEGAS with the extension is running
- **Key=value args:** `true`/`false` → booleans, numbers → numbers, everything else → strings. Paths and string values containing spaces should be quoted in the shell.
- **Pipe discovery:** The client reads `%LOCALAPPDATA%\BeckyVegas\instances\<pid>.json` files, filters to live processes, and sorts by most-recently-focused. Only the current Windows user can connect (network clients are refused by pipe security).

### Command-line tips for future agents

- **Large JSON output:** `becky-vegas timeline` produces ~960KB. Always redirect to a file and parse with `jq`, PowerShell `ConvertFrom-Json`, or a small script: `becky-vegas timeline > C:\tmp\vegas_timeline.json`
- **Finding VEGAS:** `becky-vegas instances` is the first call to make. If it returns `[]` or exits 2, VEGAS is not running, the extension didn't load, or the instance files are stale. The client filters dead processes, so a stale `.json` file in `%LOCALAPPDATA%\BeckyVegas\instances\` is harmless.
- **Checking for safety:** Always run `becky-vegas dialogs` before attempting any write command. The extension's safety guard refuses edits while a dialog is open or a render is running — the refusal names the dialog and its message text.
- **The pipe protocol:** One JSON request line in, one JSON reply line out. Request format: `{"id":1,"cmd":"status","args":{}}`. Reply format: `{"id":1,"ok":true,"result":{...}}` or `{"id":1,"ok":false,"error":"..."}`.
- **Track names:** The `timeline` command includes a `track_name` field, but in this project all tracks returned empty strings — VEGAS allows unnamed tracks. Don't rely on track names for identification; use `track` (integer index) and `kind` (video/audio) instead.

### What the bridge cannot tell you

- **Codecs / bitrates / resolutions** of individual source files — the bridge only exposes what's on the timeline (paths, in/out, positions). Use `ffprobe` or `mediainfo` on the paths for media-level metadata.
- **Waveform / thumbnail previews** — no visual frame analysis.
- **Project-level settings** beyond fps, width, height, and duration (no colour space, no proxy settings, no custom project properties).
- **Audio levels** per event — no volume/gain data is exposed in the timeline JSON.
- **Effect/FX chains** on individual events — not part of the becky-vegas contract.
